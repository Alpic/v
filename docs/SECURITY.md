# V – Security audit (pre-launch)

Date 2026-11-02. Scope: `pipeline/`, `web/`, `supabase/schema.sql`, `test/rls.sh`, `.github/workflows/`, `android/` (partial), `tools/sync_v.sh`, git history of `/home/user/playground` (46 commits) and `/home/user/v` (1 commit). Read-only audit: no code was changed.
Threat model: public GitHub Pages site with the anon key in the browser; public repo `Alpic/v` with Actions secrets; the Supabase project `kuljento` is **shared** with the other Kuljento apps; sideloaded WebView APK with a native bridge; untrusted RSS/GDELT content; free LLMs.

Summary: **Critical 1 · High 2 · Medium 6 · Low 10**. Fix pass 2026-11-02: C1, H1 (code), H2, M1-M6, L3-L10 fixed; L1, L2 (Android, > 5 lines) open. Live Supabase/GitHub settings in the release gate are still manual.

## Found along the way (fixed)
- `summarize.mjs` exported no `run`, so `hook('summarize')` was a no-op: now exported (LLM budget respected).
- APK version flow: `web/version.json` is owned by Alpic/v; sync_v.sh no longer overwrites it and pages.yml redeploys after Android (L5).
- sync_v.sh had no secret scan and the mirror no root `.gitignore` (L6).

## Needed from the crowd agent (files not touched here)
- crowd.yml: SHA-pin `checkout`/`setup-node` (same SHAs as the other workflows), add `permissions: { contents: read }`, replace `SUPABASE_URL`/`SUPABASE_SERVICE_KEY` with `V_DB_URL`.
- supabase/crowd.sql: every new `v_` table needs RLS + `grant select, insert, update, delete ... to v_writer` and a `v_writer_all` policy (re-running schema.sql after crowd.sql applies this to all `v_` tables), no anon write path (or the same size/rate caps as `v_sync_put`), anon column grants only on public columns; add rls.sh cases.
- pipeline/crowd/*: uses only select/upsert/update/rpc from db.mjs (same API); PostgREST filter subset supported: eq/neq/gt/gte/lt/lte/in/is, `not.`-prefix for is/in/eq, select, order, limit. Fetches must use `readCapped`/`readText` from net.mjs; remote text is data (no prompt injection into LLM prompts without delimiters).
- data/anchors.json: no secrets, nothing else needed.

## Positive observations
- RLS is enabled on all 8 `v_` tables; anon gets SELECT only, with column-level grants that hide `emb`/`centroid`; `v_bodies` and `v_sync` have no anon access; the writer RPCs are SECURITY INVOKER **and** revoked from anon/authenticated; schema changes touch only `v_` objects. `test/rls.sh` covers 13 cases including hashed code storage.
- The sync code has about 98 bits of entropy (`crypto.getRandomValues`, 20 chars from 30 symbols); only its sha256 is stored, and it lives in the URL fragment (never sent to servers or in Referer). Brute-forcing `v_sync_get` is infeasible.
- Git history of both repos: **no secrets** (JWT, Google, OpenRouter, GitHub, Supabase secret, private-key patterns). The only hits are prose mentions of `service_role`. No keystore or `.env` file was ever committed. Working trees are clean. `config.js` holds placeholders.
- LLM keys are sent in headers, never in URLs; only `:free` OpenRouter ids are accepted; there is a per-run call budget.
- fast-xml-parser 5.11.2 does **not** expand DTD entities (billion-laughs test: 4-char title, 7 ms). Tags are stripped from titles and leads; Preact escapes text; the QR SVG holds no user text.
- APK: `allowBackup=false`, FileProvider not exported, only a launcher intent filter, targetSdk 36 (file access off by default, cleartext blocked), the update sha256 comes from the server rather than the page, Android signature continuity, and the keystore comes from env only (`*.jks` gitignored).
- No `pull_request`/`pull_request_target` triggers. Secrets are not in the `npm ci` step env, so install scripts don't see them.
